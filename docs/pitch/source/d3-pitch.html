2. หลักการทำงานที่ต้องอธิบายได้

กรรมการมีวิศวกรอยู่ด้วย — ต้องตอบได้ลึกกว่าที่พูดบนเวที

2.1 ภาพรวมใน 4 บรรทัด

  1. เก็บสัญญาณ จากการสัมผัสหน้าจอ เซ็นเซอร์ความเคลื่อนไหว กล้อง และไมโครโฟน
  2. คำนวณค่าชี้วัด จากสัญญาณดิบ เช่น ความคลาดเคลื่อนจากเส้น หรือพลังงานย่านความถี่
  3. แปลงเป็นคะแนน 0–100 โดยเทียบกับช่วงอ้างอิง แล้วถ่วงน้ำหนักรวมกัน
  4. สรุปเป็นระดับความเสี่ยง พร้อมแยกว่าเข้ากับกลุ่มอาการใดมากที่สุด

2.2 แบบทดสอบทั้ง 5 และสิ่งที่วัด

แบบทดสอบน้ำหนักวัดอะไรหลักการ
วาดก้นหอย30% การสั่นขณะเคลื่อนไหว + การควบคุมกล้ามเนื้อมัดเล็ก สร้างเส้นตามสมการ Archimedean r = b·θ แปลงพิกัดนิ้วเป็นระบบเชิงขั้ว แล้ววัดความคลาดเคลื่อนจากเส้นแม่แบบตลอดเส้นทาง
เคาะนิ้ว25% ความเร็ว จังหวะ การช้าลง และความไม่สมมาตรสองมือ อ้างอิงโครงสร้าง MDS-UPDRS ข้อ 3.4 แบ่ง 3 ช่วง: ตามจังหวะ / เร็วสุดมือถนัด / เร็วสุดอีกมือ
ความนิ่งของมือ20% การสั่นขณะพัก และขณะยกค้าง อ่านความเร่งจากเซ็นเซอร์ แล้วทำ FFT หาพลังงานย่าน 4–7 Hz แยกวัด 2 ท่า
หันศีรษะ15% ช่วงการเคลื่อนไหว และความสมมาตร ใช้ MediaPipe ตรวจจุดสังเกตบนใบหน้า คำนวณมุมหัน (yaw) แบบเรียลไทม์
เสียงพูด10% ความสั่นของระดับเสียงและความดัง บันทึก 5 วินาที วิเคราะห์ Jitter / Shimmer / ความคงที่ของ F0 แล้วลบไฟล์ทิ้ง

2.3 สามกลไกที่เป็นความใหม่ของเรา

ก. การวัด 2 ท่า เพื่อแยกโรค

นี่คือหัวใจของการแยกกลุ่มอาการ และเป็นหลักการทางคลินิกจริง

กลุ่มอาการสั่นขณะพักสั่นขณะยกค้าง
Parkinsonian Syndromeสั่นชัดลดลง
Essential Tremorน้อยสั่นชัด
Enhanced Physiological Tremorน้อยสั่นละเอียด ความแรงต่ำ

ข. การปรับเกณฑ์ตามอายุ

ความสามารถในการเคลื่อนไหวลดลงตามวัยตามธรรมชาติ ถ้าใช้เกณฑ์เดียวกับคนหนุ่มสาว ระบบจะแจ้งเตือนผู้สูงอายุเกินจริงจนไม่มีใครใช้ เราจึงขยับเกณฑ์ “ปกติ” ให้ผ่อนปรนตามอายุ โดยอ้างอิงที่อายุ 60 ปี

ค. กฎ Red Flag

คะแนนรวมเป็นค่าเฉลี่ยถ่วงน้ำหนัก ซึ่งมีจุดอ่อนคือหักลบกันเอง ถ้าผู้ใช้มีอาการสั่นขณะพักรุนแรงเพียงรายการเดียว แต่อีก 4 รายการปกติ ค่าเฉลี่ยจะกลบสัญญาณนั้นจนรายงานว่า “ความเสี่ยงต่ำ” เราจึงกำหนดว่าถ้าแบบทดสอบใดได้ตั้งแต่ 80 คะแนนขึ้นไป ห้ามรายงานผลรวมว่าเสี่ยงต่ำเด็ดขาด

ถ้าถูกถามว่า “ทำไมย่าน 4–7 Hz”

เป็นย่านความถี่ของการสั่นแบบพาร์กินสันตามงานวิจัยที่อ้างอิง เราทำ FFT พร้อมหน้าต่าง Hann และการกำจัดแนวโน้มเชิงเส้น เพื่อไม่ให้การขยับช้า ๆ เช่นแขนตก ถูกนับเป็นการสั่น — และเรามีตัวเลขพิสูจน์ว่ามันแยกได้จริง (ดูหัวข้อ 4)

3. ตัวเลขทุกตัวมาจากไหน

กฎเหล็ก

ตัวเลขที่มาสถานะ
น้ำหนัก 30/25/20/15/10% ทีมกำหนดเอง ตามความเฉพาะเจาะจงทางคลินิกของแต่ละแบบทดสอบ ประมาณเชิงวิศวกรรม ต้องบอกตรง ๆ ว่ายังไม่ได้สอบเทียบ

โครงสร้าง 3 ช่วงของการเคาะนิ้ว MDS-UPDRS ข้อ 3.4 — แบบประเมินมาตรฐานที่แพทย์ใช้จริง อ้างอิงมาตรฐานสากล
เกณฑ์ 0–33 / 34–66 / 67–100 ทีมกำหนดเอง เพื่อแบ่งเป็นสามระดับที่สื่อสารง่าย ประมาณเชิงวิศวกรรม
เกณฑ์ red flag ที่ 80 ทีมกำหนดเอง ประมาณเชิงวิศวกรรม
ผลตรวจสอบ 21 รายการ รันจริงด้วย npm run validate ในโปรเจกต์ รันสดให้ดูได้ทันที

ระยะเวลากว่าจะได้รับการวินิจฉัย ยังไม่มีแหล่งอ้างอิง ต้องหาก่อนวันแข่ง หรือห้ามพูด

5. คำถาม-คำตอบ 3 นาที

กรรมการเน้นว่าช่วงนี้มีน้ำหนักไม่น้อยกว่าการนำเสนอ — ซ้อมส่วนนี้ให้หนักที่สุด

5.1 คำถามที่ต้องเจอแน่นอน

ความแม่นยำเท่าไร มี sensitivity / specificity ไหม
ยังไม่มีครับ เพราะยังไม่ได้ทดสอบกับผู้ป่วยที่ได้รับการวินิจฉัยจริง สิ่งที่เรามีคือการยืนยันว่าระบบวัดได้ตรงตามที่ออกแบบ 21 รายการ ทดสอบกับสัญญาณที่เรารู้คำตอบล่วงหน้า เช่น จับการสั่น 5 เฮิรตซ์ที่ถูกกลบด้วยการขยับใหญ่กว่า 125 เท่าได้ที่ 0.78 ส่วนการตรวจสอบทางคลินิกคือขั้นถัดไป ต้องทำร่วมกับโรงพยาบาลและขออนุมัติจริยธรรมการวิจัยครับ
ห้ามตอบเป็นตัวเลขที่แต่งขึ้นเด็ดขาด
ต่างจาก GFairy อย่างไร
“GFairy เสนอตัวชี้วัดใหม่ ส่วนเราเสนอการคัดกรองที่แยกกลุ่มอาการได้ บนมือถือเครื่องเดิมของผู้ป่วย โดยข้อมูลไม่ออกจากเครื่อง — เขาตอบว่าวัดอะไรได้ เราตอบว่าใครจะได้วัด”
ถ้าถูกถามลึกกว่านี้เกี่ยวกับผลงานเขา ให้ตอบตรง ๆ ว่าไม่ทราบรายละเอียด แล้ววกกลับมาที่จุดยืนของเรา ห้ามวิจารณ์ทีมอื่นเด็ดขาด
ใหม่ตรงไหน ในเมื่อมีแอปคัดกรองพาร์กินสันอยู่แล้ว
สามข้อครับ: หนึ่ง เราแยกกลุ่มอาการได้สามแบบ ไม่ใช่แค่บอกเสี่ยง/ไม่เสี่ยง โดยอาศัยการวัดสองท่าคือขณะพักกับขณะยกค้าง ซึ่งเป็นหลักการแยกโรคทางคลินิกจริง สอง ประมวลผลในเครื่องทั้งหมด ไม่มีเซิร์ฟเวอร์ ใช้ได้แม้ไม่มีอินเทอร์เน็ต สาม ปรับเกณฑ์ตามอายุและมีกฎ red flag ซึ่งแก้ปัญหาที่ระบบให้คะแนนแบบเฉลี่ยมักพลาดครับ
ปลอดภัยต่อผู้ใช้อย่างไร ถ้าผลผิดแล้วคนไข้ตกใจ หรือชะล่าใจ
เราออกแบบเผื่อทั้งสองทางครับ ฝั่งตกใจเกินจริง เราปรับเกณฑ์ตามอายุ และมีเงื่อนไขว่าถ้าข้อมูลไม่พอ ระบบจะไม่บันทึกผลเลยแทนที่จะให้คะแนนมั่ว ฝั่งชะล่าใจ เรามีกฎ red flag และในแอปเขียนไว้ชัดว่าผลปกติไม่ได้ยืนยันว่าไม่มีโรค ถ้ามีอาการควรพบแพทย์แม้ผลจะปกติ และทุกหน้ามีข้อความว่านี่คือการคัดกรอง ไม่ใช่การวินิจฉัยครับ
ข้อมูลสุขภาพและภาพใบหน้า จัดการตาม PDPA อย่างไร
ภาพใบหน้าและเสียงถูกวิเคราะห์ในเครื่องผู้ใช้ทั้งหมดแล้วลบทิ้งทันที ไม่มีการอัปโหลด เราเก็บเฉพาะตัวเลขผลคำนวณ หน้าความยินยอมมีช่องติ๊กสองช่องแยกกันและไม่ติ๊กไว้ล่วงหน้า ช่องแรกจำเป็นสำหรับการใช้งาน ช่องที่สองเป็นทางเลือกสำหรับข้อมูลแบบไม่ระบุตัวตน และมีปุ่มลบข้อมูลทั้งหมดที่ทำงานได้จริง เพราะระบบไม่มีเซิร์ฟเวอร์ จึงไม่มีฐานข้อมูลกลางให้รั่วครับ
ข้อจำกัดของผลงานคืออะไร
สามข้อหลักครับ: หนึ่ง ยังไม่ผ่านการตรวจสอบทางคลินิก ค่าเกณฑ์ทั้งหมดเป็นการประมาณเชิงวิศวกรรม สอง เซ็นเซอร์ของโทรศัพท์แต่ละรุ่นคุณภาพไม่เท่ากัน และไมโครโฟนมีอัตราขยายต่างกัน เราจึงไม่นำความดังเสียงมาคิดคะแนน สาม เรายังไม่ได้วัดอาการสำคัญบางอย่าง เช่น ลายมือที่เล็กลง (micrographia) ซึ่งอยู่ในแผนพัฒนาต่อครับ

5.2 คำถามที่อาจเจอ

ทำไมไม่ทำเป็นแอปใน App Store
เพราะกลุ่มเป้าหมายคือผู้สูงอายุครับ การให้ติดตั้งแอปเป็นอุปสรรคจริง เราเลยทำเป็นเว็บแอปที่เปิดจากลิงก์ได้ทันที แต่ยังติดตั้งลงหน้าจอโฮมได้ถ้าต้องการ และยังทำงานออฟไลน์ได้เหมือนแอปทั่วไปครับ
ผู้สูงอายุใช้เองได้จริงหรือ
เราออกแบบทั้งแอปเพื่อคนกลุ่มนี้ครับ ตัวอักษรต่ำสุด 18 พิกเซล ปรับขนาดได้ 3 ระดับทั้งแอป ปุ่มทุกปุ่มอย่างน้อย 56 พิกเซลเพื่อรองรับมือที่สั่น มีเสียงแนะนำภาษาไทย และทุกแบบทดสอบมีสามขั้นคือ ดูวิธีทำ → ทดลองใช้ → ทำจริง เพื่อไม่ให้ครั้งแรกที่ทำคือครั้งที่วัดผลครับ
ถ้าคนไข้แกล้งทำหรือทำไม่ตั้งใจ ระบบรู้ไหม
ระบบมีเงื่อนไขขั้นต่ำของข้อมูลครับ เช่น การเคาะต้องมีอย่างน้อย 6 ครั้ง การวาดต้องครอบคลุมเส้นอย่างน้อย 70% เสียงต้องมีการออกเสียงจริงอย่างน้อย 25% ของช่วงบันทึก ถ้าไม่ถึงเกณฑ์ ระบบจะไม่บันทึกผลและให้ทำใหม่ แทนที่จะให้คะแนนที่ดูดีแต่ไม่มีความหมายครับ
โมเดล AI ที่ใช้คืออะไร เทรนด้วยข้อมูลอะไร
ต้องตอบให้ตรงครับ — ส่วนการให้คะแนนไม่ใช่โมเดลที่เรียนรู้จากข้อมูล แต่เป็นการคำนวณเชิงสัญญาณตามหลักการทางคลินิกที่กำหนดไว้ชัดเจน จึงอธิบายที่มาของทุกค่าได้ ส่วนที่เป็น AI จริงคือ MediaPipe ซึ่งใช้ตรวจจับจุดสังเกตบนใบหน้าเท่านั้น
ข้อดีคือเราตรวจสอบย้อนกลับได้ทุกขั้นตอน ต่างจากโมเดลกล่องดำ ส่วนการนำ machine learning มาใช้จะทำหลังจากมีข้อมูลที่ผ่านการยินยอมมากพอครับ
จะนำไปใช้จริงได้อย่างไร ใครจะจ่าย
เริ่มจากโรงพยาบาลหรือ รพ.สต. ใช้เป็นเครื่องมือคัดกรองเบื้องต้นในชุมชนครับ เพราะไม่ต้องซื้ออุปกรณ์ใหม่เลย ใช้มือถือที่มีอยู่แล้ว ต้นทุนต่อคนจึงเกือบเป็นศูนย์ ขั้นถัดไปคือร่วมมือกับโรงพยาบาลเพื่อตรวจสอบความแม่นยำก่อน แล้วจึงขยายผลครับ
ถ้าเน็ตล่ม เดโมยังทำงานไหม
ทำงานได้ครับ แอปประมวลผลในเครื่องทั้งหมด ไม่ต้องใช้อินเทอร์เน็ตเลย — คำถามนี้เข้าทางเรามาก ถ้าถูกถามให้เปิดโหมดเครื่องบินสาธิตเลย

6. ขั้นตอนการสาธิตและแผนสำรอง

กรรมการสั่งให้เตรียมแผนสำรองไว้ในไฟล์เดียวกัน

6.1 เส้นทางสาธิตที่แนะนำ — วาดก้นหอย

เหตุผลที่เลือกแบบทดสอบนี้: เห็นผลทันทีบนหน้าจอ ไม่ต้องขออนุญาตกล้องหรือไมโครโฟน (ซึ่งอาจมีหน้าต่างขออนุญาตเด้งขึ้นมาแล้วเสียเวลา) และเส้นสีส้มที่ลากทำให้กรรมการเห็น input → analysis → result ได้ครบในหน้าจอเดียว

ขั้นทำอะไรเวลาพูดว่าอะไร
1เปิดแอปที่หน้าหลัก5 วิ“นี่คือหน้าหลัก ผู้ใช้เห็นภารกิจวันนี้และผลล่าสุด”
2แตะแบบทดสอบวาดก้นหอย5 วิ“ทุกแบบทดสอบมีสามขั้น ดู–ลอง–ทำจริง เพื่อผู้สูงอายุ”
3ข้ามไปขั้นทำจริง10 วิ“ผมข้ามไปขั้นทดสอบจริงเลยนะครับ”
4ลากนิ้วตามเส้น25 วิ“นี่คือ input — เส้นสีส้มคือเส้นที่ผมลากจริง”
5รอประมวลผล5 วิ“นี่คือ analysis — เทียบทุกจุดกับเส้นแม่แบบ แล้ววิเคราะห์ความถี่การสั่น”
6เปิดหน้าผลลัพธ์25 วิ“นี่คือ result — คะแนน ระดับความเสี่ยง และแยกตามกลุ่มอาการทั้งสาม”
7เลื่อนให้เห็นกราฟแนวโน้ม15 วิ“และเห็นแนวโน้มย้อนหลังของตัวเองได้ด้วย”

รวม 90 วินาที

6.2 แผนสำรอง 3 ชั้น

ชั้นที่ 1 — สาธิตสดบนมือถือ
แผนหลัก
  • ต่อจอผ่านสายหรือกล้องเอกสาร ตามที่งานจัดให้
ชั้นที่ 2 — วิดีโอที่อัดไว้
ถ้าต่อจอไม่ได้ หรือมือถือมีปัญหา
  • อัดวิดีโอการสาธิตทั้ง 90 วินาทีไว้ล่วงหน้า
  • ฝังไว้ในไฟล์สไลด์เดียวกัน ไม่ใช่ไฟล์แยก (กรรมการสั่งข้อนี้ตรง ๆ)
ชั้นที่ 3 — ภาพหน้าจอในสไลด์
ถ้าวิดีโอเล่นไม่ได้
  • ใช้ภาพจากเอกสารคู่มือที่ทำไว้แล้ว มีครบทุกขั้นตอน

6.3 เช็กลิสต์ก่อนขึ้นเวที

  • มือถือชาร์จเต็ม 100% + พาวเวอร์แบงก์
  • ปิดการแจ้งเตือนทั้งหมด (เปิดโหมดห้ามรบกวน)
  • ปิดการหมุนหน้าจออัตโนมัติ
  • ความสว่างหน้าจอสูงสุด + ปิดโหมดประหยัดแบตเตอรี่
  • ตั้งเวลาล็อกหน้าจอเป็น “ไม่ล็อก” หรือนานที่สุด
  • เปิดแอปค้างไว้ที่หน้าหลักก่อนขึ้นเวที
  • ลบข้อมูลเก่าและโหลดข้อมูลตัวอย่างให้กราฟไม่ว่าง
  • ไฟล์สไลด์ + วิดีโอ อยู่ใน USB 2 อัน
  • ทดสอบเปิดแอปในโหมดเครื่องบินแล้วว่าใช้ได้
  • ถึงงานก่อน 12:30 น. และส่งไฟล์ที่จุดลงทะเบียน
ประโยคปิดที่ต้องจำ
