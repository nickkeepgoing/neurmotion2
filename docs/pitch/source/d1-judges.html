2. คำแนะนำผูกกับเกณฑ์คะแนนอย่างไร

กรรมการให้คะแนน 1–5 ในแต่ละเกณฑ์ แล้วถ่วงน้ำหนักตามสัดส่วนนี้
รหัสเกณฑ์น้ำหนักคอมเมนต์ของเราแตะเกณฑ์นี้ไหม
C2ความคิดสร้างสรรค์ / ความใหม่20%ใช่ — โดยตรง ผ่านคำถาม “ต่างจาก GFairy อย่างไร”
C1ความชัดเจนและความสำคัญของปัญหา15%ทางอ้อม — ต้องมีตัวเลขที่มาของปัญหา
C3ความเหมาะสมของแนวทางแก้ปัญหา15%ทางอ้อม — Live Demo พิสูจน์ว่าแนวทางใช้ได้
C4ความเป็นไปได้ในการพัฒนา/ใช้งานจริง15%ใช่ — Live Demo คือหลักฐานตรงที่สุดว่าใช้ได้จริง
C5หลักฐานหรือเหตุผลสนับสนุน15%ใช่ — โดยตรง ผ่านคำว่า “dataset และ metric”
C6ศักยภาพผลกระทบต่อสุขภาพ/คุณภาพชีวิต12%ไม่ตรง แต่ต้องพูดถึงในช่วงท้าย
C7คุณภาพการสื่อสารและการนำเสนอ8%ใช่ — สาธิตสดที่ลื่นไหลคือการสื่อสารที่ดีที่สุด
อ่านตารางนี้อย่างไร

คอมเมนต์ของเราพุ่งไปที่ C2 (20%) + C5 (15%) + C4 (15%) = 50% ของคะแนนทั้งหมด นี่คือเหตุผลที่ทุกอย่างในแผน 5 วันควรวนอยู่กับสามเกณฑ์นี้เท่านั้น

2.1 สิ่งที่ “ได้คะแนน” กับ “ไม่ได้คะแนน”

ได้คะแนนแน่นอน
  • สาธิตสดที่ทำงานได้จริงบนมือถือ
  • ตัวเลขที่บอกที่มาได้ทุกตัว
  • ประโยคแยกตัวเองจาก GFairy
  • บอกข้อจำกัดเองก่อนถูกถาม
  • ตอบ Q&A ได้ฉับไวและตรงคำถาม
ไม่ได้คะแนนเพิ่ม (ในรอบนี้)
  • ฟีเจอร์ใหม่ที่กรรมการไม่ได้ขอ
  • ระบบ login ที่มีเซิร์ฟเวอร์จริง
  • Admin dashboard เต็มรูปแบบ
  • สไลด์สวยแต่ไม่มีของจริง
  • การอ้างความแม่นยำที่พิสูจน์ไม่ได้
เรื่อง login และ admin dashboard — ขอให้พิจารณาก่อนตัดสินใจ

คอมเมนต์ของกรรมการ ไม่ได้พูดถึง login หรือ admin dashboard เลยแม้แต่คำเดียว และการสร้างระบบยืนยันตัวตนพร้อมเซิร์ฟเวอร์ใน 5 วัน มีผลข้างเคียงที่อันตรายต่อการแข่งขัน:

  • กินเวลาที่ต้องใช้ซ้อมสาธิตสด ซึ่งเป็นสิ่งที่กรรมการขอโดยตรง
  • เพิ่มจุดพังใหม่ให้การสาธิต — ถ้าเน็ตในงานล่มหรือเซิร์ฟเวอร์ไม่ตอบ เดโมจบทันที ขณะที่ตอนนี้แอปทำงานออฟไลน์ได้ 100% ซึ่งเป็นจุดแข็งที่ควรอวด ไม่ใช่จุดที่ควรทิ้ง
  • ไม่เพิ่มคะแนนในเกณฑ์ C2 หรือ C5 ซึ่งเป็นสองเกณฑ์ที่คอมเมนต์ชี้ไป

ข้อเสนอที่ได้ทั้งสองอย่าง อยู่ในเอกสาร “แผนพัฒนาระบบ” หัวข้อ 3 — ทำ หน้าสำหรับบุคลากรแบบทำงานในเครื่อง ซึ่งใช้เวลา 1 วัน ไม่ต้องมีเซิร์ฟเวอร์ ไม่เพิ่มความเสี่ยงให้เดโม และยังแสดง roadmap ให้กรรมการเห็นได้จริง

3. คู่แข่งตรง — GFairy (M12)

กรรมการถามทั้งสองทีมให้อธิบายความต่างจากอีกฝ่าย
M12 · GFAIRY · ตัวบ่งชี้ชีวภาพทางประสาทการเคลื่อนไหว · ช่วงที่ 2

ต้องตอบให้ชัดว่า biomarker ที่ทีมเสนอคืออะไรและใหม่ตรงไหน เมื่อเทียบกับงานคัดกรอง Parkinson ที่มีอยู่ แสดงตัวอย่างข้อมูลการเคลื่อนไหว ผลการจำแนก และ metric สำคัญ พร้อมอธิบายความแตกต่างของ GFairy กับ Neuro Motion AI ให้กรรมการเห็นภายในประโยคเดียว

อ่านออกได้ 3 อย่าง:

  1. กรรมการมองว่าสองทีมนี้ทับกัน และจะเปรียบเทียบเราสองทีมแน่นอน
  2. GFairy อยู่ช่วงเวลาเดียวกับเรา (ช่วงที่ 2 · 13:00–14:20) กรรมการจะเห็นติดกัน จำได้ชัด
  3. กรรมการใช้คำว่า “ภายในประโยคเดียว” — เขาต้องการคำตอบสั้น คม ไม่ใช่คำอธิบายยาว

3.2 ประโยคที่ต้องท่องให้ขึ้นใจ

คำตอบมาตรฐาน (ใช้เมื่อถูกถามตรง ๆ)

“GFairy เสนอตัวชี้วัดใหม่ ส่วนเราเสนอการคัดกรองที่ แยกกลุ่มอาการได้ บนมือถือเครื่องเดิมของผู้ป่วย โดยข้อมูลไม่ออกจากเครื่อง — เขาตอบว่าวัดอะไรได้ เราตอบว่าใครจะได้วัด”

กติกาสำคัญเมื่อพูดถึงทีมอื่น
  • ห้ามพูดในเชิงลบกับ GFairy เด็ดขาด เราไม่รู้รายละเอียดผลงานเขา การวิจารณ์สิ่งที่เราไม่รู้จะย้อนกลับมาทำร้ายเราเอง
  • พูดถึงแกนของเรา ให้ชัด แล้วปล่อยให้ความต่างปรากฏเอง
  • ถ้ากรรมการถามเจาะรายละเอียดของ GFairy ที่เราไม่รู้ ให้ตอบตรง ๆ ว่า “ผมไม่ทราบรายละเอียดของทีมเขาครับ แต่จุดยืนของเราคือ…”

3.3 ความใหม่ของเราที่ป้องกันได้ (C2 = 20%)

ถ้าถูกถามว่า “ใหม่ตรงไหน” ให้ตอบด้วย 3 ข้อนี้ ตามลำดับความแข็งแรง

#ความใหม่ทำไมจึงป้องกันได้
1แยก 3 กลุ่มอาการ ไม่ใช่แค่บอกเสี่ยง/ไม่เสี่ยง แอปคัดกรองการสั่นทั่วไปให้คำตอบเดียว แต่เราแยก Parkinsonian / Essential Tremor / Enhanced Physiological Tremor โดยอาศัยการวัด 2 ท่า (พัก vs ยกค้าง) ซึ่งเป็นหลักการแยกโรคทางคลินิกจริง
2ประมวลผลในเครื่อง 100% ไม่มีเซิร์ฟเวอร์ ภาพใบหน้าและเสียงเป็นข้อมูลอ่อนไหวตาม PDPA เราออกแบบให้ไม่มีข้อมูลออกจากเครื่องตั้งแต่ต้น จึงไม่มีฐานข้อมูลกลางให้รั่ว และใช้งานได้แม้ไม่มีอินเทอร์เน็ต
3ปรับเกณฑ์ตามอายุ + กฎ red flag สองกลไกนี้แก้ปัญหาที่ระบบให้คะแนนแบบเฉลี่ยมักพลาด คือแจ้งเตือนผู้สูงอายุเกินจริง และค่าเฉลี่ยกลบสัญญาณผิดปกติเดี่ยว ๆ — เรามีตัวเลขพิสูจน์ทั้งสองข้อ

4. ช่องว่างที่ใหญ่ที่สุด — “metric ความแม่นยำ”

เราไม่มีข้อมูลผู้ป่วย และต้องไม่แกล้งว่ามี
ข้อเท็จจริงที่ต้องยอมรับ

เราไม่มีค่า sensitivity / specificity เพราะไม่เคยทดสอบกับผู้ป่วยที่ได้รับการวินิจฉัยจริง การสร้างตัวเลขเหล่านี้ขึ้นมาเองคือการโกหก และถ้ากรรมการซึ่งมีแพทย์ร่วมอยู่ด้วยจับได้ จะเสียคะแนน C5 ทั้งหมดและเสียความน่าเชื่อถือทั้งการนำเสนอ

4.1 สิ่งที่เรามีจริงและใช้ตอบได้

เราแยก “ความแม่นยำ” ออกเป็นสองชั้น แล้วตอบเฉพาะชั้นที่เราพิสูจน์ได้จริง

ชั้นที่ 1 — ยืนยันแล้ว ✓

“ระบบวัดได้ตรงตามที่ออกแบบไว้หรือไม่”

ทดสอบกับสัญญาณสังเคราะห์ที่เรากำหนดคำตอบไว้ล่วงหน้า เช่น สร้างคลื่นสั่น 5 Hz แล้วดูว่าระบบวัดได้ 5 Hz จริงไหม ผ่านทั้ง 21 รายการ

ชั้นที่ 2 — ยังไม่มี ✗

“ทำนายโรคในคนจริงได้แม่นแค่ไหน”

ต้องมีผู้ป่วยที่แพทย์วินิจฉัยแล้ว + กลุ่มควบคุม + การอนุมัติจริยธรรมการวิจัย นี่คือขั้นถัดไปของโครงการ และเราพูดตรง ๆ ว่ายังไม่ถึงขั้นนั้น

4.2 ผลการตรวจสอบเชิงเทคนิค 21 รายการ

5. ข้อแนะนำรวมถึงทุกทีม → เช็กลิสต์ของเรา

จากเอกสารหน้า 15 — แปลงเป็นสิ่งที่ต้องทำจริง

1 · “4 นาทีไม่ใช่เวลาสำหรับเล่าทุกอย่าง” — ตอบ 4 คำถามให้ครบและชัด

คำถามคำตอบของเรา (ฉบับย่อ)
ปัญหาคืออะไรพาร์กินสันมักถูกวินิจฉัยช้า เพราะอาการช่วงแรกไม่ชัดและการเข้าถึงแพทย์เฉพาะทางยาก
นวัตกรรมคืออะไรแอปบนมือถือที่คัดกรองด้วยแบบทดสอบ 5 อย่าง และแยกได้ว่าเข้ากับกลุ่มอาการใด
พิสูจน์อย่างไรสาธิตสด + ผลตรวจสอบเชิงเทคนิค 21 รายการ + ระบุตรง ๆ ว่ายังไม่มีการตรวจสอบทางคลินิก
แล้วจะเกิดผลอะไรผู้สูงอายุตรวจเองที่บ้านได้ใน 5 นาที เห็นแนวโน้มตัวเอง และรู้ว่าเมื่อไรควรไปพบแพทย์

2 · “ของจริงมีน้ำหนักสูงมาก”

  • เอามือถือจริง ขึ้นเวที ไม่ใช่แค่สไลด์ — และให้กรรมการเห็นว่ามันตอบสนองจริง
  • ถ้าเป็นไปได้ ให้กรรมการลองแตะเอง 10 วินาที มีน้ำหนักกว่าเราสาธิตเองมาก

3 · “ต้องรู้ที่มาของทุกตัวเลข”

ตัวเลขที่เราพูดบนเวที ต้องตอบได้ทุกตัวว่ามาจากไหน

รวมถึงตัวเลขปัญหา (เช่น จำนวนผู้ป่วยพาร์กินสันในไทย) ซึ่งต้องหาแหล่งอ้างอิงจริงก่อนวันแข่ง ถ้าหาไม่ได้ ห้ามพูดตัวเลขนั้น — ใช้คำเชิงคุณภาพแทน ปลอดภัยกว่ามาก รายละเอียดอยู่ในเอกสาร “เตรียมความรู้สำหรับ Pitch” หัวข้อ 3

4 · “อย่าปกปิดข้อจำกัด”

ข้อนี้เข้าทางเรามาก เพราะเราซื่อสัตย์เรื่องข้อจำกัดอยู่แล้ว ให้พูดเองก่อนถูกถาม — กรรมการเขียนไว้ตรง ๆ ว่า “มักสร้างความน่าเชื่อถือมากกว่าการบอกว่าผลงานพร้อมสมบูรณ์แล้ว”

5 · “เตรียม Q&A 3 นาทีให้หนักกว่าท่อง Pitch”

ช่วงถาม 3 นาที มีน้ำหนักต่อคะแนนไม่น้อยกว่าการนำเสนอ 4 นาที คำถามและคำตอบที่ต้องซ้อม อยู่ในเอกสาร “เตรียมความรู้สำหรับ Pitch” หัวข้อ 5

สรุปสิ่งที่ต้องทำ เรียงตามผลต่อคะแนน

  • ซ้อมสาธิตสดจนจบใน 90 วินาที และเตรียมวิดีโอสำรองไว้ในไฟล์เดียวกับสไลด์
  • ท่องประโยคแยกตัวจาก GFairy ให้พูดได้ทันทีโดยไม่ต้องคิด
  • เตรียมคำตอบเรื่องความแม่นยำ ที่ซื่อสัตย์และมีตัวเลขรองรับ
  • หาแหล่งอ้างอิงของตัวเลขปัญหา หรือตัดตัวเลขนั้นออกจากสคริปต์
  • ซ้อม Q&A อย่างน้อย 2 รอบเต็ม โดยให้คนอื่นถามแบบไม่บอกล่วงหน้า
  • เตรียมข้อจำกัด 3 ข้อที่จะพูดเองก่อนถูกถาม
  • เช็กว่ามือถือชาร์จเต็ม ปิดการแจ้งเตือน และตั้งความสว่างสูงสุด
