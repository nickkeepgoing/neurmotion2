2. วาดก้นหอย (Spiral Tracing) — น้ำหนัก 30%

ที่มา: การวิเคราะห์เกลียวดิจิทัล (digital spiral analysis) เป็นวิธีมาตรฐานในงานวิจัยที่ประเมินอาการสั่นและการควบคุมกล้ามเนื้อมัดเล็ก

2.1 เส้นแม่แบบ

สร้างจากสมการ Archimedean spiral: r = b·θ โดย

x = cx + b·θ·cos(θ) y = cy + b·θ·sin(θ) θ ∈ [0, 6π] (3 รอบเต็ม, SPIRAL_TURNS = 3) b = รัศมีสูงสุดที่ต้องการ / θ_max (ปรับเกลียวให้พอดีพื้นที่วาดบนจอ)

2.2 การแปลงเป็นพิกัดเชิงขั้ว และแก้ปัญหาการวน (unwrap)

สำหรับจุดผู้ใช้แต่ละจุด: r = √((x−cx)² + (y−cy)²) และหามุมด้วย atan2(y−cy, x−cx) ปัญหาคือ atan2 ให้ค่าในช่วง (−π, π] เท่านั้น เมื่อผู้ใช้วนหลายรอบ มุมจะ "กระโดด" กลับทุก 2π ระบบจึงต้อง unwrap โดยสะสม offset ±2π ทุกครั้งที่ตรวจพบการกระโดดมากกว่า π ระหว่างจุดติดกัน เพื่อให้ θ เพิ่มขึ้นต่อเนื่องตลอดทั้งการวน

2.3 การจัดตำแหน่งมุมเริ่มต้น (θ₀ registration)

จุดที่ทีมแก้บั๊กจริงระหว่างพัฒนา: ผู้ใช้เริ่มลากจากจุดศูนย์กลาง ซึ่งมุมรอบจุดศูนย์กลางไม่มีความหมายทางคณิตศาสตร์ (สัญญาณรบกวนสูงมาก) มุมเริ่มต้นที่ผิดจะกลายเป็นความคลาดเคลื่อนคงที่ b·θ₀ ตลอดทั้งเส้น — เกลียวที่ผู้ใช้วาดสมบูรณ์แบบอาจได้คะแนนแย่มากถ้าไม่แก้จุดนี้

วิธีแก้

ค้นหาค่าชดเชยมุม k ที่ทำให้ RMS ของ (r − b·(θ−k)) ต่ำที่สุด โดยกวาดค่า k ตั้งแต่ −π ถึง π ทีละ 0.02 เรเดียน และไม่ใช้จุดที่รัศมี < 15px (ใกล้ศูนย์กลางเกินไปจนมุมไม่น่าเชื่อถือ)

2.4 ค่าชี้วัดทั้ง 4 ตัว

ก. ความคลาดเคลื่อนจากเส้น (rmsErrorNorm) — น้ำหนัก 35%

error_i = r_i − b·θ_i (เฉพาะจุดที่ r_i ≥ 15px) RMS = √( Σ error_i² / n ) rmsErrorNorm = RMS / (2πb) ← หารด้วยระยะห่างระหว่างรอบ (turn gap)

เกณฑ์: ปกติ ≤ 0.05 (5% ของระยะห่างรอบ) · ผิดปกติชัดเจน ≥ 0.30

ข. พลังงานย่านการสั่น 4–7 Hz (tremorBandPower) — น้ำหนัก 30%

นำสัญญาณ "ความคลาดเคลื่อนตามเวลา" (error vs t) มา resample ให้สม่ำเสมอที่ 60Hz แล้วทำ FFT หาสัดส่วนพลังงานในย่าน 4–7Hz (วิธีเต็มอยู่ในหัวข้อ 7) เกณฑ์: ปกติ ≤ 0.03 · ผิดปกติชัดเจน ≥ 0.20

ค. ความสม่ำเสมอของระยะห่างระหว่างรอบ (spacingCV) — น้ำหนัก 15%

ทุกครั้งที่ θ ข้ามจุดครบรอบ (2π, 4π, 6π, …) บันทึกรัศมี ณ จุดนั้น แล้วหาผลต่างระหว่างรอบติดกัน (gap) spacingCV = SD(gaps) / |mean(gaps)| เกณฑ์: ปกติ ≤ 0.08 · ผิดปกติชัดเจน ≥ 0.35

ง. ความราบรื่นของการลาก (speedCV) — น้ำหนัก 20%

ความเร็ว v_i = ระยะทาง(p_i, p_{i−1}) / Δt แล้ว speedCV = SD(v) / |mean(v)| เกณฑ์: ปกติ ≤ 0.35 · ผิดปกติชัดเจน ≥ 1.0 (การกระตุกหยุดๆ ระหว่างลาก / ลายมือช้าลง)

การตัดสิทธิ์ (ไม่ใช่การให้คะแนน)

coverage = θ_สุดท้าย / θ_max ต้องครอบคลุม ≥ 70% ของเส้น มิฉะนั้นระบบจะไม่บันทึกผลเลย เพราะการลากไม่ครบทำให้ค่าชี้วัดทุกตัวไม่มีความหมาย

3. เคาะนิ้ว (Finger Tapping) — น้ำหนัก 25%

ที่มา: โครงสร้างอ้างอิง MDS-UPDRS ข้อ 3.4 — แบบประเมินการเคาะนิ้วที่แพทย์ใช้จริง

3.1 สามช่วงการทดสอบ (ช่วงละ 10 วินาที)

ช่วงทำอะไรวัดอะไรได้เฉพาะช่วงนี้
1. ตามจังหวะ (paced)เคาะตามเมโทรนอมทุก 500ms (2 ครั้ง/วิ) ด้วยมือถนัดความแม่นยำของจังหวะ
2. เร็วสุด มือถนัดเคาะเร็วที่สุด ไม่มีจังหวะนำความเร็วสูงสุด และการช้าลงระหว่างช่วง
3. เร็วสุด มืออีกข้างเหมือนข้อ 2 แต่สลับมือความไม่สมมาตรระหว่างสองมือ

เหตุผลที่ต้องแยก 3 ช่วง: ถ้าเคาะตามเมโทรนอมอย่างเดียว ทุกคนจะถูกจังหวะภายนอกบังคับให้เคาะที่อัตราเดียวกัน ทำให้วัด "ความเร็วสูงสุด" และ "การช้าลงตามเวลา (bradykinesia decrement)" ไม่ได้เลย

3.2 ค่าชี้วัด

ก. อัตราการเคาะ (rate) — น้ำหนัก 25% · จากมือที่ช้ากว่าในช่วงเร็วสุด

rate = จำนวนครั้งที่เคาะ / 10 วินาที เกณฑ์: ปกติ ≥ 5 ครั้ง/วิ (การเคาะนิ้วชี้สูงสุดผู้ใหญ่สุขภาพดี ≈ 4–6Hz) · ผิดปกติชัดเจน ≤ 2 ครั้ง/วิ

ข. ความแปรปรวนของจังหวะ (itiSD) — น้ำหนัก 20% · จากช่วงตามจังหวะ

ITI_i = t_i − t_(i−1) (ช่วงเวลาระหว่างการเคาะติดกัน, ms) itiSD = ส่วนเบี่ยงเบนมาตรฐานของ ITI ทั้งหมด

เกณฑ์: ปกติ ≤ 30ms · ผิดปกติชัดเจน ≥ 130ms

ค. ความชันของการช้าลง / decrement (decrementSlope) — น้ำหนัก 20% · ค่าแย่กว่าจากสองมือในช่วงเร็วสุด

คำนวณด้วย least-squares regression ของ ITI เทียบกับลำดับการเคาะ i: slope = Σ(i−ī)(ITI_i−ITĪ) / Σ(i−ī)² ความชันเป็นบวก = ช่วงห่างยาวขึ้นเรื่อยๆ = เคาะช้าลงตามเวลา (สัญญาณ bradykinesia) เกณฑ์: ปกติ ≈ 0 ms/ครั้ง · ผิดปกติชัดเจน ≥ 5 ms/ครั้ง

ง. ค่าคลาดเคลื่อนของจังหวะ (timingError) — น้ำหนัก 15% · จากช่วงตามจังหวะ

phase_i = (t_i − t_0) mod 500 error_i = min(phase_i, 500 − phase_i) timingError = mean(error_i)

เกณฑ์: ปกติ ≤ 50ms · ผิดปกติชัดเจน ≥ 180ms

จ. ความไม่สมมาตรสองมือ (asymmetry) — น้ำหนัก 20% · จากอัตราสูงสุดสองมือ

asymmetry = (อัตราเร็วสุด − อัตราช้าสุด) / อัตราเร็วสุด → 0 = สองมือเท่ากัน, ใกล้ 1 = มือข้างหนึ่งแทบเคาะไม่ได้ เกณฑ์: ปกติ ≤ 0.10 · ผิดปกติชัดเจน ≥ 0.45

ทำไม asymmetry ถึงสำคัญ

พาร์กินสันระยะแรกมักไม่สมมาตรสูง (เริ่มข้างเดียวก่อน) ค่านี้จึงเป็นหนึ่งในสัญญาณที่แยกโรคได้ดีที่สุด และเป็นเหตุผลที่ต้องทดสอบทั้งสองมือ ไม่ใช่มือเดียว

4. ความนิ่งของมือ (Rest & Postural Tremor) — น้ำหนัก 20%

ที่มา: การสั่นขณะพักคือสัญญาณที่จำเพาะที่สุดของโรคพาร์กินสัน — ปรากฏเมื่อแขนอยู่นิ่งและมีที่รองรับ

4.1 สองท่าทดสอบ (คนละ 8 วินาที สุ่มตัวอย่างที่ 60Hz)

ท่าทำอย่างไรวัดอะไร
ยกค้าง (postural)ถือโทรศัพท์ยกขึ้น แขนลอย ไม่มีที่พักการสั่นขณะออกแรง/คงท่า (action tremor)
พัก (rest)วางแขนพักบนโต๊ะ/ตัก ถือโทรศัพท์นิ่งๆการสั่นขณะพัก (rest tremor) — จำเพาะสุด

4.2 ค่าชี้วัด (คำนวณแยกทั้งสองท่าด้วยวิธีเดียวกัน)

resample ขนาดความเร่ง (acceleration magnitude) ให้สม่ำเสมอที่ 60Hz จากนั้น:

RMS (แอมพลิจูด) = √( Σ(x_i − mean)² / n ) หน่วย m/s² bandPower = สัดส่วนพลังงานในย่าน 4–7Hz (วิธีเต็มในหัวข้อ 7)
ค่าชี้วัดน้ำหนักปกติผิดปกติชัดเจน

กลุ่มอาการสั่นขณะพักสั่นขณะยกค้าง

ตารางนี้คือ "รูปแบบชี้แนะ" ตามหลักการทางคลินิกทั่วไป ไม่ใช่การวินิจฉัยแยกโรคที่ผ่านการรับรองในแอปนี้ — แอปใช้มันเพื่อ "ชี้ทิศทาง" ให้ผู้ใช้คุยกับแพทย์ ไม่ใช่ฟันธง

5. หันศีรษะ (Head-Turn Range of Motion) — น้ำหนัก 15%

ที่มา: หลักการตรวจเส้นประสาทสมอง/การเคลื่อนไหวคอ — พิสัยลดลง ไม่สมมาตร หรือเคลื่อนไหวกระตุก สัมพันธ์กับโรคทางระบบประสาท
หมายเหตุความซื่อสัตย์ — ต่างจากเอกสารออกแบบเดิม

เดิมออกแบบไว้เป็นแบบทดสอบ "ยิ้ม" (smile) ด้วย MediaPipe Face Landmarker แต่เวอร์ชันที่ implement จริง เปลี่ยนเป็นการหันศีรษะซ้าย–ขวา เพราะวัดได้เสถียรกว่าบนกล้องมือถือที่คุณภาพหลากหลาย ถ้ากรรมการถามอิงจากเอกสารเก่า ให้ตอบตรงตามที่ทำจริงในแอป

5.1 การประมาณมุมหัน (yaw) จากจุดสังเกตบนใบหน้า

ใช้ MediaPipe Face Landmarker ตรวจจุด 468 จุดบนใบหน้าแบบเรียลไทม์ แล้วประมาณมุมจากตำแหน่งปลายจมูก

mid = (จุดขอบแก้มซ้าย.x + จุดขอบแก้มขวา.x) / 2 half = |จุดขอบแก้มขวา.x − จุดขอบแก้มซ้าย.x| / 2 proxy = clamp( (จมูก.x − mid) / half , −1.4, 1.4 ) yaw (องศา) = −proxy × 60 (proxy=1 ↔ ประมาณ 60°)

เครื่องหมายลบเพื่อชดเชยว่าเฟรมกล้องดิบไม่ได้ถูกกลับด้าน (mirror) เหมือนภาพพรีวิวที่ผู้ใช้เห็น

5.2 ค่าชี้วัด (จากเฟรม {t, yaw} ที่เก็บระหว่างการหัน ~6 วินาที)

centre = median(yaw ทั้งหมด) ← ลดผลจากกล้องที่ไม่อยู่กึ่งกลางพอดี rightDeg = max(0, max(yaw) − centre) leftDeg = max(0, centre − min(yaw)) turnRangeDeg = leftDeg + rightDeg turnAsymmetry = |leftDeg − rightDeg| / max(leftDeg, rightDeg, 1)

6. เสียงพูด (Sustained Vowel "อาา") — น้ำหนัก 10%

ที่มา: jitter/shimmer จากเสียงสระเปล่งค้าง เป็นวิธีมาตรฐานในงานวิจัยเสียงพาร์กินสัน (อ้างอิงแนวทาง Little et al. 2009)

6.1 การเก็บสัญญาณ

บันทึกเสียง 5 วินาทีผ่าน Web Audio API — ปิด autoGainControl โดยตั้งใจ เพื่อไม่ให้ระบบขยายเสียงเบา ขึ้นอัตโนมัติจนวัดแอมพลิจูดจริงไม่ได้ วิเคราะห์ในเครื่องแล้วลบไฟล์ทันที ไม่มีการอัปโหลด

6.2 การตัดเฟรมและตรวจจับความถี่มูลฐาน (F0)

ตัดสัญญาณเป็นเฟรมยาว 40ms ทุก 20ms (ซ้อนทับ 50%) แต่ละเฟรมหา F0 ด้วย normalized autocorrelation ในช่วง 70–400Hz:

corr(lag) = Σ x[i]·x[i+lag] / energy โดย energy = Σ x[i]² bestLag = lag ที่ให้ corr สูงสุด ในช่วง [sampleRate/400, sampleRate/70] F0 = sampleRate / bestLag ถ้า corr สูงสุด > 0.5 มิฉะนั้น = 0 (ไม่มีเสียง)

เฟรมที่ใช้ได้ (voiced) ต้องมี F0 > 0 และ RMS แอมพลิจูด > 0.005 — voicedRatio = สัดส่วนเฟรมที่ใช้ได้ ต้อง ≥ 25% จึงจะให้คะแนน มิฉะนั้นถือว่าทดสอบไม่สำเร็จ

6.3 ค่าชี้วัด

ก. Jitter (%) — น้ำหนัก 40% — ความแปรปรวนคาบเสียงจากรอบสู่รอบ

T_i = 1 / F0_i (คาบเสียงแต่ละเฟรม) jitter% = mean(|T_i − T_(i−1)|) / mean(T) × 100

เกณฑ์: ปกติ ≤ 0.6% · ผิดปกติชัดเจน ≥ 2.5%

ข. Shimmer (%) — น้ำหนัก 35% — ความแปรปรวนความดังจากรอบสู่รอบ

shimmer% = mean(|A_i − A_(i−1)|) / mean(A) × 100 A = RMS แอมพลิจูดของแต่ละเฟรม

เกณฑ์: ปกติ ≤ 3.5% · ผิดปกติชัดเจน ≥ 11%

ค. ความไม่คงที่ของระดับเสียง (f0CV) — น้ำหนัก 25%

f0CV = SD(F0 ทุกเฟรมที่ใช้ได้) / mean(F0) เกณฑ์: ปกติ ≤ 0.015 · ผิดปกติชัดเจน ≥ 0.09

สิ่งที่ตั้งใจ "ไม่วัด"

ความดังเสียง (loudness) ไม่ถูกนำมาคิดคะแนน เพราะไมโครโฟนแต่ละรุ่นโทรศัพท์มี gain ต่างกัน และเบราว์เซอร์ไม่เปิดค่าความดังเป็นหน่วย SPL จริง มิเตอร์ในแอปเป็นเพียง "ตัวช่วยบอกว่าดังพอหรือยัง" การวัด hypophonia (เสียงเบาผิดปกติ) ที่แม่นยำต้องใช้อุปกรณ์ที่สอบเทียบแล้ว

7. กลไกร่วม: วิธีจับ "การสั่น" จากสัญญาณดิบ

ใช้ร่วมกันในแบบทดสอบวาดก้นหอย (สัญญาณ error ตามเวลา) และความนิ่งของมือ (สัญญาณความเร่ง)

7.1 ทำไมต้องแปลงเป็นโดเมนความถี่

การสั่นแบบพาร์กินสัน (4–7Hz) มักถูกซ่อนอยู่ใต้การเคลื่อนไหวช้าที่มีพลังงานสูงกว่ามาก เช่น การเลื่อนมือช้าๆ หรือความโค้งของเกลียวเอง การดูค่าเฉลี่ยหรือค่าเบี่ยงเบนมาตรฐานในโดเมนเวลาแยกสองสิ่งนี้ไม่ออก ต้องแปลงเป็นสเปกตรัมความถี่ (FFT) แล้วดูว่าพลังงานอยู่ในย่านเป้าหมายมากแค่ไหน

7.2 ขั้นตอนเต็มของ bandPowerRatio()

  1. เติมศูนย์ (zero-pad) ให้ความยาวสัญญาณเป็นเลขยกกำลังสองที่ใกล้ที่สุด — ข้อกำหนดของ FFT แบบ radix-2 Cooley–Tukey ที่ใช้
  2. ลบแนวโน้มเชิงเส้น (linear detrend): หาความชัน m ด้วย least-squares แล้วลบ mean + m×(i−mid) ออกจากทุกจุด — ตัดการเคลื่อนไหวช้าๆ เช่น แขนตกหรือมือลอย มิฉะนั้นพลังงานจากมันจะ "รั่ว" ทับย่าน 4–7Hz
  3. คูณด้วยหน้าต่าง Hann: w[i] = 0.5×(1 − cos(2πi/(N−1))) — ลดการรั่วไหลของสเปกตรัมจากขอบสัญญาณ (รูปสี่เหลี่ยม/rectangular รั่วที่ −13dB ส่วน Hann รั่วที่ −31dB และลาดชันกว่ามาก)
  4. ทำ FFT ได้ค่าจริง/จินตภาพของแต่ละความถี่ย่อย (bin) k ซึ่งสอดคล้องความถี่ f = k × (sampleHz/N)
  5. กำลังของแต่ละ bin: P[k] = re[k]² + im[k]²
  6. ผลรวมทั้งหมด (denominator) คิดเฉพาะย่าน 0.5Hz ถึง min(15Hz, Nyquist) — ตัด DC และความถี่สูงมากออก ไม่ให้เศษ drift ที่เหลือมาครองสัดส่วนทั้งหมด
  7. bandPowerRatio = (ผลรวมกำลังใน 4–7Hz) / (ผลรวมกำลังทั้งหมดใน 0.5–15Hz)

8. จากค่าชี้วัดดิบ → คะแนน 0–100 → ระดับความเสี่ยง

ทุกสูตรอยู่ใน scoring.ts และ thresholds.ts

8.1 normalize เป็นคะแนนย่อยของ metric หนึ่งตัว

score(x) = clamp( (x − good) / (bad − good) × 100 , 0, 100 )

good = ค่าที่ถือว่า "ปกติ" (คะแนน 0) · bad = ค่าที่ถือว่า "ผิดปกติชัดเจน" (คะแนน 100) สูตรนี้รองรับทั้งกรณี bad>good (ยิ่งค่าสูงยิ่งน่ากังวล เช่น jitter) และกรณีกลับด้าน bad<good (เช่น พิสัยการหันศีรษะ ยิ่งค่าน้อยยิ่งน่ากังวล) โดยอัตโนมัติ

8.2 ปรับเกณฑ์ตามอายุ (age-adjusted range)

ความสามารถในการเคลื่อนไหวลดลงตามวัยตามธรรมชาติ ถ้าใช้เกณฑ์เดียวกับคนหนุ่มสาว ระบบจะแจ้งเตือน ผู้สูงอายุเกินจริง สำหรับผู้ใช้อายุมากกว่า 60 ปี (AGE_REF):

decades = min( (age − 60) / 10 , 3 ) ← เพดานที่ 3 ทศวรรษ (ราว 90 ปี) กันเกณฑ์หย่อนไร้ความหมาย good_ปรับแล้ว = good + (bad − good) × shift × decades

shift เป็นสัดส่วนเฉพาะของแต่ละ metric เช่น อัตราเคาะสูงสุด shift=0.12 หมายถึงเกณฑ์ปกติหย่อนลงราว 12% ของช่วง good→bad ต่อทศวรรษ สอดคล้องกับงานวิจัยว่าอัตราการเคาะสูงสุดในผู้ใหญ่สุขภาพดีลดลงราว 5–8% ต่อทศวรรษ

8.3 รวมเป็นคะแนนของแบบทดสอบหนึ่งอย่าง (sub-score)

subScore = Σ( score(metric_i) × weight_i ) / Σ weight_i

เฉลี่ยถ่วงน้ำหนักเฉพาะ metric ที่มีข้อมูลจริงในครั้งนั้น

8.4 รวมเป็นคะแนนรวมทั้งเซสชัน

overall = Σ( subScore_j × W_j ) / Σ W_j

เฉพาะแบบทดสอบที่ทำจริงในเซสชันนั้น — ทำ 3 จาก 5 แบบก็คำนวณได้ตามสัดส่วนที่มี ไม่ต้องรอครบ 5 แบบ

8.5 แปลงเป็นระดับความเสี่ยง + กฎ Red Flag

0–33 ต่ำ (เขียว) · 34–66 กลาง (เหลือง) · 67–100 สูง (แดง)

ปัญหาของค่าเฉลี่ยถ่วงน้ำหนัก: มันหักลบกันเอง

ถ้ามีแบบทดสอบเดียวที่คะแนนสูงมาก (เช่น สั่นขณะพักชัดเจน) แต่อีก 4 แบบปกติ ค่าเฉลี่ยจะกลบสัญญาณอันตรายนั้น จนดูเหมือน "ต่ำ" — โรคพาร์กินสันระยะแรกมักแสดงอาการเฉพาะจุด (domain-selective) และไม่สมมาตร ระบบที่เฉลี่ยล้วนๆ จะจับได้ก็ต่อเมื่อโรคลุกลามจนกระทบทุกด้านแล้ว ซึ่งเลยจุดที่การคัดกรองยังมีประโยชน์

กฎ

ถ้า subScore ของแบบทดสอบใดก็ตาม ≥ 80 (RED_FLAG_SUBSCORE) และค่าเฉลี่ยรวมออกมาเป็น "ต่ำ" ให้ยกระดับเป็น "กลาง" ทันที — ไม่มีทางถูกรายงานว่าต่ำอีกต่อไป

8.7 การนับวันเสี่ยงสูงต่อเนื่อง

นับเฉพาะวันปฏิทินติดต่อกันย้อนจากวันนี้ (หรือเมื่อวานถ้ายังไม่ทำวันนี้) ที่ผลออกมา "สูง" ทุกวัน — ขาดไปแม้วันเดียวตัดสายทันที เมื่อครบ 5 วันติดต่อกัน (RISK_STREAK_DAYS) ระบบจะแจ้งเตือนให้พบแพทย์

9. ข้อจำกัดของแบบจำลองนี้ — ต้องพูดเองก่อนถูกถาม

ความน่าเชื่อถือมาจากการบอกขอบเขต ไม่ใช่จากการอ้างว่าสมบูรณ์
ระดับความน่าเชื่อถือของค่าตัวเลขในเอกสารนี้

ค่า good / bad / weight ทุกตัวใน thresholds.ts เป็น "การประมาณเชิงวิศวกรรม" ที่ทีมกำหนดขึ้นเอง ไม่ใช่ค่าที่ผ่านการสอบเทียบทางคลินิกกับผู้ป่วยจริง มีเพียงย่านความถี่ 4–7Hz และโครงสร้าง MDS-UPDRS ข้อ 3.4 เท่านั้นที่มีที่มาจากวรรณกรรม/มาตรฐานสากลโดยตรง

ข้อจำกัดรายละเอียด
ยังไม่มีค่า sensitivity / specificity เพราะยังไม่ทดสอบกับผู้ป่วยที่ได้รับการวินิจฉัยจริง สิ่งที่ยืนยันได้คือ "ระบบวัดตรงตามที่ออกแบบ" (21/21 รายการใน npm run validate) ไม่ใช่ความแม่นยำทางคลินิก
เซนเซอร์แต่ละรุ่นคุณภาพไม่เท่ากัน โดยเฉพาะไมโครโฟนที่มี gain ต่างกันมาก จึงตัดความดังเสียงออกจากการให้คะแนนโดยตั้งใจ
ยังไม่ครอบคลุมอาการสำคัญบางอย่าง เช่น micrographia (ลายมือเล็กลง) อยู่ในแผนพัฒนาต่อ
ไม่ใช่ machine learning เป็นการคำนวณเชิงสัญญาณตามกฎที่กำหนดไว้ชัดเจน ข้อดีคือตรวจสอบย้อนกลับได้ทุกขั้นตอน ข้อเสียคือยังไม่ได้ "เรียนรู้" จากเคสจริงเพื่อปรับตัวเอง
